The producer's independent nixpkgs, rust-overlay and craft-fonts also advance;
consumers must use exact producer outputs instead of overriding that toolchain.
GitHub's anonymous API quota interrupted ordinary tag resolution. The recovery
used public-Git-verified commits and Nix-generated immutable fetch/lock hashes,
then retained the canonical original tag URLs. No credentials, fake hash, stale
channel fallback or permanent second pin table is introduced.

Eighteen exact Cargo Git source strings (including unused patches) remain
fail-closed; twelve new trees were prefetched and hash-pinned. Registry checksums
and original Cargo locks remain upstream-owned. Actual Cargo vendor builds decide
whether archive and Git tree hashes match; metadata alone is not acceptance.
PDF retains its paired official Rust 1.98.1 compiler/std exception until an actual
unoverridden RTen build demonstrates retirement; it is not a global host rollback.
Default English OCR models/notices remain pinned from upstream attribution.

## New application boundaries

- FigCraft, TextureCraft and MaterialCraft use the shared Rust GUI/CLI packaging,
  wrappers, code/font/asset notices and upstream Linux desktop/icon/MIME resources.
- Craft Anything supplies GUI and CLI but declares no Linux document MIME type;
  packaging checks that explicit exception instead of inventing one or skipping
  other apps' MIME checks. Its original NOTICE/attribution is installed.
- The runtime dialog checker is copied by content, retaining the exact regression
  while avoiding full-suite rebuilds for unrelated documentation changes.
- No updater/agent account is invoked during packaging. Craft Anything's setup,
  provider-probing doctor, capture, rebuild, engine/plugin installers and live
  targets remain separate runtime permissions. Its Clean room mode is not an OS
  sandbox. The consumer/policy owner handles its disabled Pi declaration/skill.

## Licensing and validation

PhotoCraft's Linux tests now receive a store-configured private D-Bus daemon.
Its memory detector correctly refuses PSD/TIFF imports when the ordinary Nix
sandbox hides cgroup constraints. A test-only Cargo wrapper therefore creates a
private user/filesystem/network/cgroup namespace, mounts its read-only cgroup v2
view and drops all child capabilities before running the unchanged Cargo test
arguments. No application memory guard, daemon setting or host mount is changed.
Linux checks require those namespace/kernel facilities and fail if unavailable.
The fast `photocraft-check-environment` check exercises the real upstream memory
detector's positive/negative unit cases plus readable constraints and zero child
capabilities. [Recipe](../packages/craft.nix) · [check](../tests/photocraft-check-environment.nix).

Sixteen native apps retain MIT/Apache code licenses plus their own asset notices.
ArtCraft studio remains separately non-free: only its permitted local personal
build is approved. It stays excluded from automatic free checks and consumer
installation; no binary cache/artifact publication is authorized. Source-only
mirroring remains separate and is not triggered by this feature push.

[Validation evidence and limits](validation.md) separates current native builds,
installed CLI/MCP/GUI fixtures, non-native evaluation and historical receipts.
Synthetic software rendering cannot certify physical GPU/audio/portal devices,
real provider/auth behavior or external engines. No consumer activation is implied.
